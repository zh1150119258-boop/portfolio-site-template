# 参考网站复刻（高保真、按证据做）

目标：照着主人认可的参考网站，做出**同样的版式、动效和交互体验**，但**内容全部是主人自己的**。
不是「凭感觉做一个风格相似的页面」，而是每个组件都能对应到记录下来的证据。

本技能和 `cloudflare-portfolio-site` 配合使用：复刻的是网站「外观和交互」这一层（`app/(site)/`、`app/_site/`、`app/globals.css`），
后台、R2 数据、转码、播放规则、部署、SEO 这些底座不因为复刻而推倒重来。

## 先说清楚的边界

- **版权**：参考站的文字、图片、视频、商标、字体文件（除非是开源字体）不能放进主人的网站。只参考版式、比例、节奏和交互；内容和素材全部换成主人的。和主人说清楚这一点。
- 不确定能否访问（需要登录、有付费墙、明确禁止抓取）时停下来，告诉主人，不要猜隐藏的状态。
- 不说「像素级一模一样」，除非那个状态、那个尺寸真的测过。
- **打不开参考站时**：在网页版 Claude Code（claude.ai/code）里，云端环境的网络设置可能不允许访问这个网站（工具报 `ERR_TUNNEL_CONNECTION_FAILED` 或 403）。告诉主人网站名，请他在环境设置的「网络访问」里把这个域名加进允许列表，或换成更宽的访问级别（说明：https://code.claude.com/docs/en/cloud-environments#network-access ）。也可以用 Claude in Chrome 在主人自己的浏览器里截图、量尺寸作为证据。不要凭印象补。

## 必须遵守

1. 不凭记忆或审美发挥；不从一张静态截图猜交互。
2. 只测首屏不算完成；每个状态（加载、菜单、悬停、点击、打开 / 关闭、播放、返回、深色模式）都要点过。
3. 每个实现的组件都能说出对应的证据（哪张截图、哪段录制、哪个检测结果）。
4. 复刻优先级：版式结构 40%、交互动效和路由 40%、字体配色间距 15%、原站文字和图片 5%（内容换成主人的，但尺寸、比例、裁切、层级和状态要一致）。
5. 原站做法看起来「不常规」时也先照做并验证，不要悄悄换成更简单的近似。
6. 视觉和性能一起考虑：大的开场动画、首屏多个视频、WebGL 都会拖慢手机，做之前告诉主人代价。

## 工具（在 `tools/clone/`，命令已写进 package.json）

| 命令 | 作用 |
|---|---|
| `pnpm clone:fingerprint <参考网址>` | 检测参考站用了什么技术（框架、视频、平滑滚动、GSAP、Canvas、WebGL），决定用什么方式实现 |
| `pnpm clone:capture <交互计划.json> --url <网址>` | 按计划在指定时间点（例如 0 / 50 / 180 / 500 毫秒）截下交互过程，用来看打开、关闭、滚动的动画 |
| `pnpm clone:compare <对比清单.json> --source-url <参考站> --candidate-url http://localhost:3000` | 参考站和本地页面做同样的操作，同尺寸截图，逐像素对比 + 元素位置、尺寸、样式、文字对比，出报告 |
| `pnpm clone:diff <参考.png> <本地.png> <差异图.png>` | 两张同尺寸截图生成差异图 |

计划 / 清单的写法参考 `tools/clone/examples/`（`interaction.plan.json`、`fidelity.matrix.json`）。
截图和报告都写在 `.workbench/`（已忽略，不提交）。工具需要 Playwright 自带的 Chromium，第一次用如果提示缺浏览器，运行 `pnpm exec playwright install chromium`。

## 步骤

### 0. 准备
1. 和主人确认：参考哪个网站、哪几页、哪些部分要像（整站？只要首页的滚动效果？只要作品详情的打开动画？），要不要手机版（作品集一般要）。
2. 记下参考网址到 `docs/clone/<站点名>/target-url.txt`。
3. 跑 `pnpm clone:fingerprint <网址>`，把确认过的结论写进 `docs/clone/<站点名>/技术分析.md`。

### 1. 录证据（先录再写代码）
- 尺寸：电脑 1440×1000 和 1280×900；要手机版加 390×844。
- 每个页面截全图；记下字体（字体名、字号、行高、字重）、颜色、间距、媒体框比例和裁切、图层顺序。
- 交互巡检，每一项都在每个尺寸做一遍：慢慢上下滚动；快速滚动看惯性；悬停每个可能的目标；点每个按钮、卡片、标题、导航；打开每个菜单、弹层、作品详情；用关闭按钮、点背景、Esc、滚动、浏览器后退分别关闭；改变窗口大小；停着不动看有没有自动播放或循环动画。
- 重要的动画用 `pnpm clone:capture` 在多个时间点截图，打开和关闭分开录。
- 结论写进 `docs/clone/<站点名>/交互记录.md`：每个状态写清触发方式、开始 / 中间 / 结束状态、时长和缓动、证据截图。

### 2. 建模
写好再动手：
- `页面结构.md`：有哪些页面、区块、浮层、固定层，谁盖在谁上面。
- `设计规范.md`：颜色、字体、间距、圆角、阴影、断点的具体数值。
- `组件清单.md`：拆成哪些组件、对应主人网站的哪一页（作品列表、作品组、详情、关于、联系），主人有而参考站没有的页面怎么处理（先问主人）。

### 3. 选实现方式（按证据，不按习惯）
- 普通版式和交互：语义化 HTML + CSS。
- 简单固定动画：CSS 过渡 / 关键帧。
- 复杂时间线、滚动联动、钉住：检测到参考站用 GSAP 时再 `pnpm add gsap @gsap/react`，在客户端组件里用，并保证离开页面时清理干净。
- 平滑滚动：参考站用了（如 Lenis）才加。
- 3D / 着色器效果：确认参考站真的在用 WebGL 改变几何、透视、像素时才用 Three.js；只是位移、透明度、裁切的用 CSS。
- 视频继续用本模板的播放规则（封面 → 预览 → 流畅 → 原画），只换外观和过渡。

### 4. 分层实现
顺序：字体和设计规范 → 全站外壳（页头、菜单、页脚、转场、光标、深浅色）→ 各页静态版式 → 导航和路由 → 滚动 / 悬停 / 拖动 → 媒体加载和播放 → 打开 / 关闭过渡 → 加载中、出错等次要状态。
每完成一块跑 `pnpm typecheck` 和 `pnpm lint`；每完成一页 `pnpm dev` 本地预览。

### 5. 对照验收
1. 参考站和本地页面同尺寸、同时机截图；能写成清单的用 `pnpm clone:compare` 批量对比，单张用 `pnpm clone:diff`。
2. 每处差异写出原因（证据错了、实现偏了、加载时机、动画时长 / 缓动、断点规则、缺状态），修正后再对比。视频画面、字体渲染、WebGL 会有无害的像素噪声，可以遮罩，但要写明理由。
3. 给主人看电脑和手机的左右对比截图，确认后再做下一页。

### 6. 完成标准
- `pnpm typecheck`、`pnpm lint`、`pnpm build` 通过，浏览器控制台没有意外报错。
- 要求的尺寸都检查过；交互记录里每个状态都实际操作过；直接打开网址、后退、打开、关闭、加载中都正常。
- 重要动画在中间时间点核对过；文字不重叠、不跳动；WebGL / Canvas 不是空白。
- 网站上没有参考站的文字、图片、视频、商标。
- 剩下的差异写进 `docs/clone/<站点名>/对照报告.md`，告诉主人。
